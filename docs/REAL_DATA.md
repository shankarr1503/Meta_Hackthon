# Real machine examples

Open `http://127.0.0.1:8000/?view=real` or select **Real recordings**.

These examples contain accelerometer measurements collected from a physical laboratory
motor, belt, pulleys, bearings and rotor. They are not generated by FailureLab's simulator.
The dashboard includes the source authors' photograph of that apparatus. Faults were
deliberately introduced by the experimenters; these are not operational factory failures
or a live connection to a machine owned by this project.

## Source and attribution

Lucas Brito, Gian Antonio Susto, Jorge Nei Brito and Marcus Duarte (2022),
*Mechanical faults in rotating machinery dataset (normal, unbalance, misalignment,
looseness)*, Mendeley Data, version 1, DOI
[10.17632/zx8pfhdtnb.1](https://data.mendeley.com/datasets/zx8pfhdtnb/1).
Data and the unmodified test-bench photograph are used under
[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). The authors do not endorse
FailureLab. This project adds feature extraction, plot previews, an evaluation split and
AI assessments. The dataset is third-party evidence; our analysis code is original.

The authors document 20 tests, five per condition, with four accelerometer channels
sampled at 25 kHz. The shaft speed is approximately 1238 RPM. The apparatus was
dismantled and returned to normal before introducing each test condition.

## Selection, integrity and split

We selected the first naturally sorted `.npy` recording from each of the 20 source ZIP
archives, before assessing outcomes. Each selected file contains four channels and
25,000 samples: one second per test. The downloader reads ZIP entries using HTTP byte
ranges, checks the entry CRC, validates shape and finite values, and records the selected
file's SHA-256. We do not claim to have verified whole-archive hashes: we downloaded
selected entries rather than the complete archives. The original advertised archive
hashes remain in the manifest with `archive_hash_verified: false`. The complete source
photograph's SHA-256 was verified.

For each condition, the first three source trials are labelled references and the last
two are held-out tests. This yields 12 reference trials and eight held-out trials.
We do not split adjacent windows of a recording between reference and test. This is
still one apparatus with few trials, not independent validation across machines.

`backend/data/real/manifest.json` records the source links, archive member names and
recording hashes. `analysis-plan.json` records the split, feature list, feature-code
hash and system-prompt hash before API calls. Raw selected samples are local and
Git-ignored; regenerate them using the command below. The derived measured examples,
source photograph, original manifest and recorded model replies are shareable artifacts.

## Analysis

The dedicated measured-data path computes per-sensor RMS, crest factor, kurtosis and
the spectral peak near 1x, 2x and 3x shaft frequency, using a mean-centred signal and a
Hann-windowed FFT. Waveforms show a downsampled first 50 ms; spectra show 0–1,000 Hz.
Features use the full selected second. The source amplitude unit has not been verified;
we keep native units rather than invent a conversion to g, displacement or temperature.

The baseline standardises log features using reference trials, then chooses the nearest
class centroid. Meta receives labelled reference features and only sensor 1 of a held-out
query initially. It can inspect each of the other three recorded sensors and must assess
within four calls. It cannot command new physical experiments. Query labels, source
filenames and trial numbers are excluded from its prompts. Raw model replies and the
inspection sequence are retained. The label is revealed in the dashboard on request;
this UI reveal is an explanatory step, not an access-control boundary.

No simulator likelihood, simulated feature, inferred temperature or calibrated fault
probability is used in this path. The normal, unbalance, misalignment and looseness
classes belong to this dataset and are not silently mapped to the simulator's classes.

## Observed results

Muse Spark 1.3 classified 6/8 held-out real trials correctly, matching the baseline's
6/8. Its 95% Wilson accuracy interval is 40.93%–92.85%, reflecting the small sample.
All eight model assessments completed without a model error, using 32 calls. Meta
inspected all four sensors for every query. It labelled both held-out looseness trials
as unbalance. The baseline misclassified one normal trial and one looseness trial.
All outcomes remain in the report; there was no retry based on correctness.

These results demonstrate end-to-end processing of genuine measurements. They do not
establish industrial reliability, calibrated confidence or a Meta advantage. A stronger
future study needs more trials, independent rigs and measured physical amplitude units.

## Reproduce

```sh
python scripts/tasks.py real-data
python scripts/tasks.py check
```

The first command downloads selected real recordings and makes at most 32 model calls
on the first run. Existing recorded assessments are reused. It needs network access and
the local Meta configuration for the initial assessment. To regenerate the derived report
from already downloaded signals and recorded replies without a model call:

```sh
backend/.venv/Scripts/python backend/scripts/real_examples.py
```

On Linux/macOS use `backend/.venv/bin/python`. Tests check split separation, recomputed
scores, replayed model actions and, when the local raw files are available, exact feature
and preview reproduction from their verified source bytes.
