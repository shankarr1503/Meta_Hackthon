## Project name

FailureLab AI

## Tagline

An AI investigator that finds out why a machine vibrates by running experiments, states
what it expects to see before every result, and answers your questions from the evidence.

## Problem

When a rotating machine starts to vibrate, the alarm names a symptom, not a cause.
Imbalance, misalignment and a failing bearing can look alike at one operating point, so an
engineer has to decide which speed and load to test next. Every test costs time and
machine downtime, and the reasoning behind a diagnosis is rarely written down.

The stakes are documented: Siemens' industry survey
[The True Cost of Downtime 2024](https://assets.new.siemens.com/siemens/assets/api/uuid:1b43afb5-2d07-47f7-9eb7-893fe7d0bc59/TCOD-2024_original.pdf)
(checked 3 November 2026) estimates that unplanned downtime costs the world's 500
biggest companies $1.4 trillion a year — 11% of their revenues. One lost hour costs up
to $2.3 million in automotive (over $600 a second) and up to $150,000 even for small
and mid-size manufacturers; the average large plant loses $253 million a year. The same
report names vibration among the key machine-health signals for predictive maintenance,
and reports that adopters have halved their unplanned downtime. The expensive part of a
vibration problem is not the sensor, it is deciding what to measure next.

## What it does

FailureLab AI hands that investigation to a Meta model (Muse Spark 1.3) and makes every
step inspectable:

1. It reads the maintenance note and sets starting beliefs. Every possible fault keeps at
   least 5%, so a wrong or malicious note cannot rule out the truth.
2. A Bayesian engine ranks experiments by expected information per cost point; the model
   picks one of the top five and **states the reading it expects under each hypothesis
   before the experiment runs**.
3. A physics simulator (a digital twin of a rotor on bearings) produces the measurement.
   The engine updates the probabilities, and the dashboard shows each prediction next to
   the measurement and which hypotheses gained or lost.
4. At 90% confidence or when the budget runs out, the model explains the diagnosis, the
   remaining doubts and the check to do next — and the dashboard adds a maintenance
   action plan for that fault class: where to look, likely root causes, ordered actions,
   and how to confirm the fix from the same measurements.
5. The engineer can then **question the investigator**: "Why not imbalance?" The model
   answers from the recorded evidence, quoting the readings and operating points; the
   answer is shown, never stored, and cannot change a number.
6. Any seed names an **unseen machine**: a new hidden fault generated by the simulator that
   neither we nor the model know in advance. Judges can investigate one live.
7. **Film your own machine** (experimental): upload a video and the browser extracts the
   vibration of one tracked point frame by frame — the clip never leaves the computer.
   The same spectrum math shows the motion peaks and shaft harmonics, and the Meta model
   reads the extracted features, flagging when the frame rate cannot resolve the machine
   speed. A ground-truth test recovers a known synthetic signal exactly; the output is
   labelled experimental and uncalibrated, and feeds no benchmark or probability.

The model never supplies a measured value or a scored probability, and never sees the
hidden fault. Any model failure falls back to the information-gain planner for that step
and is logged; every reply is stored, so each investigation replays exactly. A separate
view applies the model to real accelerometer recordings from a physical laboratory rig,
where it inspects the sensors one by one with the labels hidden.

## How we built it

Python (FastAPI, NumPy, Pydantic) and React (TypeScript, Vite, Recharts, React Three
Fiber), all written during the hackathon. The Meta Model API is called through an
OpenAI-compatible chat-completions adapter with timeouts, length caps and validation.
Investigations stream live to the dashboard as Server-Sent Events. Studies are
pre-registered: a frozen plan (hashes of code, prompts and splits) is written before the
first model call. 336 backend and 94 frontend tests, an architecture test that blocks any
path from the investigator to the hidden fault, a CI workflow that passes on GitHub for
Linux and Windows plus a container build, and a one-command Docker image with a Render
blueprint.

## Evidence

All simulated unless marked. Sources are in `backend/results/` and are re-checked by tests.

| Evidence | Result |
|---|---|
| Rule planners, 150 simulated runs each | Information gain 99.3% correct at 2.15 experiment points; fixed sweep 96.0% at 2.99; random 98.0% at 3.90 |
| Meta, 18 sealed simulated runs (same runs for the baseline) | 100% correct at 1.78 points vs 2.33 for information gain; 0 fallbacks |
| Meta, paired challenge: 24 new simulated machines × no note, misleading note, prompt-injection note | 23/24 correct in every condition, equal to information gain; injection never reached an explanation; no cost advantage (1.92–1.96 vs 1.875 points) |
| Meta, **measured laboratory recordings**: 8 held-out trials, one rig (study real-2) | Meta 8/8 (95% interval 67.6%–100%); reference-distance baseline 5/8 |
| Feature pipeline on a **second** public lab rig (exploratory): 20 held-out segments across normal, unbalance, misalignment, bearing defect (Zenodo, CC BY 4.0) | Feature baseline 20/20. Segments are correlated within one session, so this shows the pipeline is not tuned to one apparatus, not independent validation; no Meta call |
| Ask the investigator, grounding audit: 10 live questions about committed Meta replays, including an injection attempt and an unanswerable one | 10/10 answered; 194/194 quoted numbers traced back to the evidence record; no injected text in any answer |
| Live Meta demo replays committed for every sealed case and two unseen machines | 8/8 correct, 28 model calls, 0 fallbacks |

Honest limits: the simulator results use the same physics family the engine assumes, so
they show the method works, not real-world accuracy. A Meta cost advantage was seen only
on the small sealed sample. Identical prompts reuse a recorded reply, so in the challenge
the injection prior was in effect sampled once. Eight recordings from one rig are
promising, not proof of industrial reliability. Our first real-data study (real-1, 6/8 vs
6/8) placed the harmonic bands at the documented 1238 RPM while the rig runs at
1,260–1,302 RPM; we found this in code review, kept real-1 as superseded and
pre-registered real-2.

## What's next

- **Still-image intake.** Video vibrometry already reads motion from a clip; the
  remaining step is a photo or thermal image of the machine, where a multimodal Meta
  model reads what is visible — coupling wear, leaked grease, a missing balance
  weight, a hot bearing housing — and turns it into starting hypotheses and
  recommended checks. It would feed the same Bayesian loop as a prior, never as a
  measurement, keep the 5% floor so a misleading photo cannot rule out the truth, and
  ship only with a labelled-image validation study, the same bar as the recordings path.
- **More rigs and independent recordings**, calibrated amplitude units and temperature
  channels; a pre-registered Meta study on the second rig already checked exploratorily.
- **Closing the loop on hardware:** letting the model request new physical test points
  on a connected rig, so the investigation it plans runs on the machine itself.
